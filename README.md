# Параллельный учебный корпус EN / ZH / RU

Учебный параллельный корпус (английский, китайский, русский) для отработки
лексико-грамматических соответствий. В корпусе размечены три явления:

| Язык | Явление | Инструмент |
|---|---|---|
| EN | артикли *a / an / the* и существительное, к которому они относятся | spaCy |
| ZH | счётные слова 量词 в конструкции «числительное / 这 / 那 / 几 / 每 + 量词 + существительное» | jieba + редактируемый список 量词 |
| RU | падеж, число и лемма существительных | pymorphy3 + контекстные правила |

Проект сделан для курсовой работы «Параллельный учебный корпус (английский/китайский/русский)
как инструмент отработки лексико-грамматических соответствий: проектирование и апробация
на примере ИИ-ассистированной сборки».

> Полная инструкция (сайт, деплой, скриншоты) появится в README по мере готовности
> веб-интерфейса. Ниже — работа с pipeline.

## Структура репозитория

```
pipeline/                  Python 3.11: обработка текстов → corpus.json
  align/                   выравнивание: LaBSE (алгоритм Bertalign), bertalign, Гейл–Чёрч
  annotate/                разметка: en.py (артикли), zh.py (量词), ru.py (падежи)
  resources/zh_classifiers.tsv   редактируемый список счётных слов
  config.yaml              все настройки pipeline
  tests/                   pytest
data/raw/<text_id>/        входные тексты: en.txt, zh.txt, ru.txt, meta.json
data/manual/overrides.json ручные правки (импорт из CSV)
data/llm_cache/            сохранённые ответы LLM-проверки
logs/build_report.md       журнал последней сборки
web/public/data/           результат: corpus.json, corpus.csv, stats.json
```

## Установка (Windows)

1. Установите [Python 3.11](https://www.python.org/downloads/) (при установке отметьте
   «Add python.exe to PATH»).
2. В папке проекта откройте PowerShell и выполните:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r pipeline\requirements-dev.txt
python -m spacy download en_core_web_sm
```

Если PowerShell запрещает запуск скриптов, выполните один раз
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

На Linux/macOS то же самое: `python3.11 -m venv .venv && source .venv/bin/activate`.

### Необязательно: нейросетевое выравнивание LaBSE

```powershell
python -m pip install -r pipeline\requirements-neural.txt
```

При первом запуске будет скачана модель LaBSE (~1,8 ГБ). Без этих пакетов pipeline
автоматически использует метод Гейла–Чёрча и пишет об этом в журнал сборки.

### Необязательно: LLM-проверка

Скопируйте `.env.example` в `.env` и впишите ключ `ANTHROPIC_API_KEY`. Модель и
лимиты задаются в `pipeline/config.yaml` (секция `llm`). Без ключа модуль пропускается.

## Запуск

```powershell
python -m pipeline check      # проверить входные тексты
python -m pipeline build      # собрать корпус
python -m pipeline build --no-llm   # собрать без запросов к LLM
pytest                        # тесты
```

Результат: `web/public/data/corpus.json`, `corpus.csv`, `stats.json` и журнал
`logs/build_report.md` (время этапов, число пар, предупреждения, правки LLM).

## Как устроена сборка

1. **Сегментация**: pysbd (EN), razdel (RU), для ZH — по 。！？；… с учётом
   закрывающих кавычек 」”.
2. **Выравнивание**: EN — опорный язык. Пары EN–ZH и EN–RU выравниваются отдельно
   (соответствия 1–1, 1–2, 2–1), затем объединяются в тройки по английским
   предложениям. Если число абзацев во всех файлах совпадает, выравнивание идёт
   внутри абзацев. Метод `auto`: bertalign → LaBSE → Гейл–Чёрч.
   Для каждой тройки записываются `alignment_type` (например, `1-2-1`) и
   `alignment_score` (0…1, по более слабой из двух пар).
3. **Разметка** хранится как позиции символов (`start`, `end`) внутри сегмента —
   текст не изменяется.
4. **Ручные правки** из `data/manual/overrides.json` применяются до разметки.
5. **LLM-проверка** (если есть ключ): пары с низким `alignment_score` и спорная
   разметка отправляются модели; вердикт и предложение исправления пишутся в
   `llm_note`. Сами данные модель не меняет.

## Добавление текста

1. Создайте папку `data/raw/<id_текста>/` (латиница, без пробелов).
2. Положите туда `en.txt`, `zh.txt`, `ru.txt` в UTF-8. Абзацы разделяйте пустой строкой —
   если число абзацев совпадает, выравнивание будет точнее.
3. Создайте `meta.json`:

```json
{
  "title": "A Rainy Saturday",
  "title_ru": "Дождливая суббота",
  "title_zh": "一个下雨的星期六",
  "source": "Откуда текст",
  "topic": "Тематика",
  "level": "A2"
}
```

4. Выполните `python -m pipeline check`, затем `python -m pipeline build`.

## Ручная проверка через CSV

1. Откройте `web/public/data/corpus.csv` в Excel («Данные → Из текста/CSV», кодировка UTF-8).
2. Исправьте текст в колонках `en` / `zh` / `ru`, поставьте статус
   (`checked` / `corrected`, можно по-русски: «проверено», «исправлено»; `delete` / «удалить» —
   убрать пару), добавьте комментарий.
3. Сохраните как **CSV UTF-8** (иначе иероглифы потеряются).
4. Выполните `python -m pipeline import-csv путь\к\файлу.csv`: правки попадут в
   `data/manual/overrides.json`, корпус пересоберётся, исправленный текст будет
   размечен заново. Разделитель (запятая или точка с запятой) определяется автоматически.

## Ограничения

- Тексты корпуса составлены и переведены с помощью ИИ (Claude) для демонстрации
  и требуют проверки преподавателем.
- Метод Гейла–Чёрча опирается только на длину предложений; на свободных переводах
  точнее LaBSE.
- Разметка автоматическая: pymorphy3 не видит синтаксиса, поэтому часть падежей
  определяется эвристиками и помечается как спорная; jieba ошибается в границах слов
  и частях речи, поэтому существительное после 量词 ищется по правилам.
