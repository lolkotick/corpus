## 1. Pipeline корпуса (#1)

**Что сделано.** Коммиты `92703e0`–`ebae54c`.
- **Сегментация.** EN — pysbd, RU — razdel, ZH — правила по 。！？；…; закрывающие кавычки остаются с предложением.
- **Выравнивание** с опорным языком EN: EN–ZH и EN–RU выравниваются отдельно и объединяются в тройки. Соответствия 1–1 / 1–2 / 2–1; при совпадении числа абзацев выравнивание идёт по абзацам.
- **Разметка.** Артикли — spaCy; 量词 — jieba и редактируемый список из 62 счётных слов; падежи — pymorphy3 и контекстные правила. Разметка хранится позициями символов и не меняет текст.
- **Сервисные функции.** Необязательная LLM-проверка; импорт ручных правок из CSV; экспорт `corpus.json` / `corpus.csv` / `stats.json`; журнал сборки.
- **Данные.** 6 текстов уровней A1–C1; 110 троек предложений.

**Проблемы и решения** (по описанию #1 и журналу сборки):

| Проблема | Решение |
|---|---|
| Модель LaBSE не скачивалась в среде сборки: `huggingface.co` отвечал 403 | Корпус выровнен запасным методом Гейла–Чёрча. В журнале сборки остались предупреждения `bertalign: пакет не установлен`, `labse: пакет не установлен (sentence_transformers)`. На своём компьютере pipeline переключится на LaBSE после установки `requirements-neural.txt` |
| Пакет bertalign 2.x требует Python ≥ 3.12, проект на 3.11 | Алгоритм Bertalign реализован в `pipeline/align/embedding.py`. Сам пакет используется, если установлен. Алгоритм проверен тестом на поддельных эмбеддингах |
| jieba ошибается в границах слов («三 \| 本书») | Конструкция с 量词 ищется по символам, jieba только проверяет границы («统一个» не размечается) |
| pymorphy3 без синтаксиса даёт много неоднозначных падежей | Добавлены контекстные правила: предлоги, согласование, числительные, «у X есть Y», порядок слов и др. Неоднозначных разборов стало 28 из 348 (без правил было 101). Решения по порядку слов помечены уверенностью 0,85 |
| Нет ключа API в среде сборки | LLM-проверка на реальном API не запускалась; логика проверена тестами с поддельным клиентом |
| `corpus.csv` должен открываться в Excel | Файл хранится в UTF-8 с BOM, без нормализации переводов строк — CRLF (`e79b81a`) |

**Решения.**
- Тексты в корпусе упорядочены по уровню A1 → C1 (`ebae54c`).
- Ответы LLM кэшируются в `data/llm_cache/` и хранятся в git: сборка без ключа применяет уже полученные ответы.

## 4. Упражнения (#4)

**Что сделано.** Задания генерируются из предложений корпуса: EN — артикль, ZH — выбор 量词 из четырёх, RU — форма слова. К каждому заданию объяснение; есть версия для печати с ключами.

**Решения.**
- Отвлекающие 量词 не должны оказаться верными. Исключаются:
  - 量词, встречавшиеся с этим существительным в корпусе;

  - «широкие» 种 / 些 / 群 / 份.
- Для падежей неоднозначные и несклоняемые слова исключены, тривиальные задания (форма совпадает с леммой) — не более 20 %.

## 6. Этап 1: золотой стандарт (#6)

**Ревизия перед этапом.** Pytest (87), Vitest (31), линтеры и сборка сайта прошли. Пересборка корпуса воспроизводима: меняются только дата и время сборки. Поэтому отдельный PR с исправлениями основной части не понадобился (описание #6).

**Что сделано.**
- **Формат `corpus.json` версии 2** (`6a739a1`): у каждой пары есть номера предложений, у текстов — список предложений. Без этого выравнивание нельзя сравнить с эталоном.
- **Режим «Проверка» на сайте** (`94564c1`):
  - выборка пар по seed, пропорционально размеру текстов;
  - вердикты «верно / ошибка / исправление» для выравнивания и каждой пометки;
  - матрица соответствий предложений, отметка пропусков, горячие клавиши;
  - `localStorage`, экспорт и импорт `gold.json`.
- **`pipeline/evaluate.py`** (`56f4423`): точность, полнота и F1 с 95% ДИ Уилсона; строгая и мягкая оценка выравнивания; матрица ошибок по падежам.

**Решения.**
- Эталон составляет только эксперт. Скрипты `gold.json` не создают; для тестов — синтетические файлы с пометкой `synthetic: true`.
- **Выборка одинакова на сайте и в Python.** Генератор mulberry32 и алгоритм выборки реализованы на обоих языках; совпадение проверяется тестом на общем файле `pipeline/tests/fixtures/sample_crosscheck.json`.
- **Устаревание эталона.** Эталонная пара хранит снимок текста. Если после пересборки текст изменился, пара исключается из расчёта как устаревшая.

## 7. Этап 2: сравнение методов выравнивания (#7)

**Что сделано.**
- `pipeline/compare_aligners.py` запускает bertalign, LaBSE, Гейла–Чёрча, LLM (при ключе API) и базовый метод «по порядку» в одинаковых условиях.
- Отчёт: метрики по эталону, время, согласие методов и 10 расхождений.

**Результат в среде сборки** (`reports/aligners.md`):
- bertalign и LaBSE пропущены — пакеты не установлены, модели недоступны; LLM пропущен — нет ключа API;
- выполнены Гейл–Чёрч и базовый метод. Согласие между ними: 90,1 % предложений EN (EN–ZH) и 96,4 % (EN–RU);
- метрик качества нет, потому что нет эталона.

**Решение.** Методы сравниваются на уровне троек EN–ZH–RU, как пары попадают в корпус: эталон размечается на тех же тройках.

## 8. Этап 3: анализ ошибок (#8)

**Что сделано.** `pipeline/error_analysis.py` классифицирует ошибки, отмеченные экспертом, правилами:
- выравнивание: сдвиг, объединение, разделение;
- артикли: пропуск, лишнее срабатывание, неверная вершина;
- 量词: пропуск, ложное срабатывание, граница сегментации, неверное существительное;

**Проблема и решение.** В синтетических тестовых данных этапа 1 позиция артикля «a» искалась первым вхождением буквы и попадала внутрь слова «has». Генератор исправлен: теперь ищется целое слово (`7765538`).

## 10. Этап 5: материалы для курсовой (#10)

**Что сделано.**
- `pipeline/corpus_report.py` — описание корпуса (таблицы и графики из реальных данных).
- `pipeline/reports.py` + `scripts/build_reports.py` + `make reports` — все отчёты одной командой.
- `pipeline/docx_export.py` — копии отчётов в Word.

**Проблемы и решения.**
- **Графики мельче полосы набора.** Сохранение с обрезкой полей давало картинки шириной около 13,4 см вместо 16. При вставке в Word на ширину полосы разрешение падало бы ниже 300 dpi. Графики теперь сохраняются в точном размере 16 см (компоновка `constrained`); это проверяет тест.
- **Нет шрифта с иероглифами.** В среде сборки нет CJK-шрифта для matplotlib, поэтому на графиках счётные слова подписаны пиньинем; иероглифы — в таблицах.
- **Не удалось проверить Word-файлы визуально.** LibreOffice в среде сборки не открывал файлы, поэтому .docx проверены структурно: таблицы, подписи, рисунки, шрифты (тесты).

## 11. Импорт реальных данных: Tatoeba и корпус ООН

**Что сделано.**
- `pipeline/importers/tatoeba.py` — тройки EN–ZH–RU из открытых выгрузок Tatoeba. Китайский перевод — только в упрощённых иероглифах (проверка OpenCC). Для каждого предложения сохраняются номер, автор и лицензия.
- `pipeline/importers/un_corpus.py` — фрагмент корпуса ООН v1.0: построчно выровненные файлы или попарные выгрузки OPUS UNPC, объединённые по английскому предложению.
- Общие фильтры: длина, дубликаты, хотя бы одно из трёх явлений; выборка с фиксированным seed.
- `pipeline/difficulty.py` — оценка сложности по длине и частотности лексики; пороги откалиброваны на учебных текстах.
- Регистр у каждого текста; сравнение регистров в `stats.json`, на сайте и в `reports/corpus.md`.
- Страница «Источники», атрибуция в карточке пары, `attribution.csv`.

**Проблемы и решения.**
- **Источники недоступны из среды сборки.** Серверы Tatoeba, ООН, OPUS и Hugging Face отвечали 403 (политика сети). Импорт выполнен в GitHub Actions (`.github/workflows/import.yml`): там сеть открыта, результат закоммичен в ветку PR.
- **Официальный архив ООН огромный.** Полностью выровненный подкорпус — около 82 ГБ в четырёх частях, для загрузки нужна регистрация. Поэтому взяты попарные выгрузки того же корпуса на OPUS (en–zh и en–ru); архивы читаются без распаковки, тройки собираются по совпадающему английскому предложению.
- **Мусор в данных ООН.** В первой выборке были заголовки прописными, пункты таблиц и обрывки. Кроме того, одинаковые английские заголовки из разных документов получали переводы из другого места (например, «OF THE UNITED ARAB EMIRATES … ADDRESSED» с несовпадающими ZH и RU). Добавлены два фильтра: только законченные предложения и без английских строк, повторяющихся в файлах. Из первой выборки (2000 троек) проверку на законченное предложение прошли бы только 356, поэтому число просматриваемых строк увеличено с 1 до 3 млн.
- **Наборы теста изменились бы после импорта.** Предтест и посттест строятся по корпусу детерминированно. С 2600 новыми парами из прежних 30 заданий осталось бы 5, и участники, начавшие апробацию до обновления, получили бы другой посттест. Наборы теперь строятся только по учебным текстам; проверено, что они совпадают с наборами из `main` (задания, ответы, варианты).
- **Поиск стал тяжёлым.** Без запроса страница выводила все 2600 пар (десятки тысяч элементов DOM). Результаты выводятся по 50 с кнопкой «Показать ещё».
- **Ошибка в упражнениях, найденная на реальных данных.** Для артикля прописными («THE» в заголовке) варианты ответа были «A / An / The», и правильного ответа среди них не было. Варианты теперь пишутся так же, как ответ.
